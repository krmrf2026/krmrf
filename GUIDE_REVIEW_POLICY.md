# Редакционные сведения и плановая сверка KRM РФ

Политика с 25 ноября 2026 года. KRM РФ публикует датированные материалы и не гарантирует постоянную актуальность всех инструкций. Новые статьи и короткие дополнения предпочтительнее полного переписывания архива.

## Что означают даты

- `datePublished` — первоначальная публикация; URL и дата сохраняются.
- `dateModified` — содержательное изменение или датированное дополнение, а не техническая сборка.
- `reviewedAt` — последняя фактически завершённая сверка источников. Смена политики её не меняет.
- `reviewAfter` — внутренний ориентир: `reviewedAt` плюс `reviewCadenceDays`, а не публичная гарантия. По умолчанию 180 дней, допустимы 1–180 дней. Старые действующие записи переведены на 180 дней без изменения `reviewedAt`.
- `reviewStatus: current` — последняя редакция была сверена, а не подтверждение действующих на сегодня правил. `review-due` — известна необходимость уточнения; архивный и заменённый статусы сохраняются.
- `reviewBlocker` — конкретная критическая проблема. QA по-прежнему блокирует её и недостоверные/несогласованные метаданные.
- `reviewNote` — необязательное датированное дополнение (`date`, `text`, `url`, `label`). Ссылка HTTPS, дата не позже `dateModified`. Блок выводится над исходным текстом и не переписывает его.

Даты рассчитываются по Europe/Moscow. Публичные карточки, поиск и шапки показывают историческую дату сверки, явные предупреждения или архивный статус; отсчёта и обещания «актуально» нет. Внутренний срок не изменяет публичный статус автоматически. Досье проверяются при поступлении новых сведений, без календарного напоминания; совместимые поля сохраняются. Обычные датированные новости не требуют плановой сверки.

## Как работать

Ежемесячный workflow публикует необязательную сводку; корректный календарный срок не блокирует QA. Существенные изменения закона, критические ошибки и недостоверные контакты требуют уточнения по событию, даже до окончания 180 дней. Приоритетные основания указаны в `editorial/review-priorities.json`. По недвижимости отдельно следить за сроком 1 января 2027 года. Просрочка не повод переписывать текст или фиктивно датировать проверку.

Можно выпустить самостоятельную новую статью и добавить ссылку/пояснение к старой. Для `reviewNote` записать дату, короткий текст и источник в реестре, `dateModified`, `revisionHistory` и `review-due`, если полного фактчекинга ещё не было. Известную опасную ошибку нельзя оставить без явного исправления или ограничения применения. В случае замены отметить старую запись `superseded` и `supersededBy`. Для новых дополнений не использовать массовое `content:lock`: исходный текст защищён прежним манифестом.

```bash
# Необязательная сводка
npm run guides:report
# Только после фактической сверки выбранного материала
npm run guides:review -- --id=ID --date=YYYY-MM-DD
npm run build
npm run content:check
npm run qa:visible
```

Массовая фиксация дат без ID запрещена. Ручной `--strict-warning` сохранён для диагностики, но не используется в плановом workflow. `--sync-status` сохранён для совместимости команд сборки; он проверяет метаданные, но не меняет статус по календарю. Технические проверки не заменяют проверку закона, контакта или обстоятельств события. Контракт поиска `review: {status, checked, due}` сохранён для Булочкина; старые версии бота могут продолжать показывать свой срок и требуют отдельной корректировки интерфейса.
