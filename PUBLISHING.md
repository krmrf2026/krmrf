# Как публиковать материалы на новом сайте KRM РФ

## Главное правило

При обычной публикации вручную меняются только:

1. отдельная HTML-страница материала;
2. изображения материала;
3. одна запись в `data/pages.json`.

Остальное обновляет JavaScript-сборщик:

- главную;
- `/news/`;
- тематические индексы;
- `/kremennaya/`;
- `/reference/`;
- `/assessment/`;
- `/war-crimes/`;
- `/archive/`;
- внутренний поиск;
- `news.json`;
- `assessment.json`;
- `war-crimes.json`;
- `search-index.json`;
- `site.json`;
- `sitemap.xml`;
- Atom-ленты.

`news.json`, `assessment.json`, `war-crimes.json`, `search-index.json`, sitemap, Atom и карточки разделов вручную больше не редактировать.

---

## Один раз настроить Cloudflare Pages

В настройках проекта Cloudflare Pages указать:

- **Build command:** `npm run check`
- **Build output directory:** `.`
- **Root directory:** оставить пустой
- **Node.js:** версия 20 или новее

После этого при каждом `git push` Cloudflare сам выполнит сборку и проверку.

Даже если сборка Cloudflare временно не запустится, основные каталоги в браузере читают `pages.json` через `assets/js/catalog.js`. Но sitemap, Atom и статическая резервная разметка полностью обновляются именно командой сборки.

## Обычная последовательность публикации

### 1. Создать папку страницы

Примеры:

```text
/news/kremennaya/krm-2026-06-24/
/news/svo/svo-2026-06-24/
/news/reference/novaya-pamyatka/
/assessment/2026-06-28/
/war-crimes/novoe-dosye/
```

Внутри должен находиться файл:

```text
index.html
```

### 2. Скопировать страницу того же типа

- статья — последнюю качественную статью;
- памятка — последнюю памятку;
- оценка — последнюю оценку;
- досье — последнее досье.

Не копировать оценку как основу памятки и наоборот.

### 3. Изменить HTML

Обязательно проверить:

- `<title>`;
- `meta description`;
- canonical;
- Open Graph;
- Twitter Card;
- JSON-LD;
- H1;
- дату публикации;
- дату обновления;
- статус;
- текст;
- изображения и alt;
- источники;
- связанные материалы.

### 4. Добавить изображения

Примеры каталогов:

```text
/assets/img/news/kremennaya/krm-2026-06-24/
/assets/img/news/reference/novaya-pamyatka/
/assets/img/assessment/2026-06-28/
/assets/img/war-crimes/novoe-dosye/
```

### 5. Добавить одну запись в `data/pages.json`

Минимальный пример обычной статьи:

```json
{
  "id": "krm-2026-06-24",
  "type": "article",
  "title": "Кременная: транспорт и дороги в июне",
  "url": "/news/kremennaya/krm-2026-06-24/",
  "section": "kremennaya",
  "datePublished": "2026-06-24",
  "dateModified": "2026-06-24",
  "status": "confirmed",
  "excerpt": "Короткое описание для карточек, поиска и лент.",
  "image": "/assets/img/news/kremennaya/krm-2026-06-24/cover.webp",
  "imageAlt": "Описание главного изображения",
  "topics": ["daily", "infrastructure"],
  "locations": ["Кременная", "ЛНР"]
}
```

### 6. Запустить одну проверочную команду

```bash
npm run check
```

Она сначала обновит весь сайт, затем проверит ошибки.

Успешный результат выглядит так:

```text
Сборка завершена: ... публикаций.
Проверка пройдена: ... ошибок нет.
```

### 7. Открыть сайт локально

```bash
npm run serve
```

Открыть:

```text
http://localhost:8000/
```

Проверить:

- новую страницу;
- главную, если материал должен быть на ней;
- тематический раздел;
- архив;
- поиск;
- мобильную ширину.

### 8. Отправить в ветку

```bash
git add -A
git commit -m "Добавлен материал о ..."
git push origin noviy-sait
```

После этого проверить Cloudflare Preview.

## Допустимые значения полей

### `type`

```text
article      обычная статья или аналитический материал
guide        практическая памятка
assessment   оценка фронта
dossier      досье
```

### `section`

```text
kremennaya       Кременная
svo              СВО
lnr              ЛНР
law              справочник
civilian-impact  гражданские последствия
politics         старый архивный раздел политики
assessment       оценки фронта
warcrimes        досье
```

### `topics`

Поле необязательное. Особенно полезно для хроники Кременной и поиска.

Текущие темы Кременной:

```text
safety          безопасность и БПЛА
daily           повседневная жизнь
infrastructure  дороги, транспорт, связь и городская среда
history         история и память
```

### `locations`

Поле необязательное, но улучшает архивный поиск и фильтр.

Пример:

```json
"locations": ["Кременная", "ЛНР"]
```

### `period`

Используется для оценок фронта:

```json
"period": "22–28 июня 2026"
```

## Как управлять главной

Главная обычно выбирает:

- последнюю оценку автоматически;
- последние материалы разделов автоматически, если ручной выбор не указан.

Для точного ручного выбора используется поле `home`.

### «Последнее важное»

```json
"home": {
  "important": 1
}
```

Числа `1`, `2`, `3` задают порядок трёх карточек.

### Блок Кременной

```json
"home": {
  "kremennaya": 1
}
```

### Блок справочника

```json
"home": {
  "guide": 1
}
```

### Блок досье

```json
"home": {
  "dossier": 1
}
```

Материал может участвовать только в нужных ему блоках. Необязательно добавлять `home` каждой публикации.

---

## Что происходит автоматически

После изменения `pages.json`:

- `catalog.js` обновляет карточки главной и разделов в браузере;
- `archive-filter.js` строит архив и ищет по заголовку, описанию, тексту, теме и территории;
- `search.js` объединяет `pages.json` с полнотекстовым индексом;
- `npm run build` обновляет статические HTML-карточки и все технические файлы;
- `npm run validate` останавливает публикацию при ошибке.

---

## Что не нужно редактировать вручную

После внедрения автоматизации не редактировать вручную:

```text
data/news.json
data/assessment.json
data/war-crimes.json
data/search-index.json
data/site.json
sitemap.xml
feed.xml
assessment/feed.xml
kremennaya/feed.xml
карточки в индексах
строки в архиве
```

Исключение — только ремонт самой системы сборки.

---

## Обновление существующей публикации

### Только опечатка

Изменить HTML и выполнить:

```bash
npm run check
```

### Изменились заголовок, дата, описание или изображение

Изменить:

1. HTML;
2. соответствующую запись в `data/pages.json`;
3. выполнить `npm run check`.

Все карточки, поиск, архив, sitemap и ленты обновятся автоматически.

---

## Если проверка сообщает ошибку

Не выполнять merge в `main`, пока `npm run check` не завершится успешно.

Сообщение укажет конкретную проблему:

- отсутствует HTML;
- отсутствует изображение;
- неправильный canonical;
- два одинаковых ID;
- два одинаковых URL;
- битая ссылка;
- невалидный JSON;
- отсутствующий H1;
- неисправный JavaScript.
