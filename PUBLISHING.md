# Публикация материалов KRM РФ

Эта инструкция рассчитана на обычную публикацию одним автором. Готовый сайт остаётся статическим HTML/CSS/JS/JSON-проектом.

## Главное правило

Для новой публикации вручную создаются только:

1. HTML-страница материала;
2. исходные изображения; производные версии 480/960 WebP создаёт локальная проверка;
3. одна запись в `data/pages.json`.

Главную, индексы, архив, поиск, производные JSON, sitemap и Atom вручную не редактировать. Их обновляет `npm run check`.

## Обычная публикация

### 1. Создать рабочую ветку

```bash
git switch main
git pull
git switch -c publish/kratkoe-nazvanie
```

### 2. Создать страницу того же типа

Копируйте последний качественный пример:

- статья — `/news/.../index.html`;
- памятка — `/news/reference/.../index.html`;
- оценка — `/assessment/.../index.html`;
- досье — `/war-crimes/.../index.html`.

Не меняйте существующие URL и тексты других публикаций.

### 3. Проверить HTML

Обязательно заполните:

- `<title>` и description;
- canonical, Open Graph и Twitter Card;
- один H1;
- дату публикации;
- изображение и alt;
- текст, статус сведений, источники и ограничения;
- JSON-LD. Метаданные Article затем синхронизирует сборщик.

### 4. Добавить изображения

Оригинал хранится в обычном каталоге публикации. Для главной обложки должны существовать версии:

```text
/assets/img/derived/.../cover-480.webp
/assets/img/derived/.../cover-960.webp
```

Команда `npm run check` создаёт отсутствующие версии через ImageMagick. Созданные WebP нужно добавить в тот же commit. Если ImageMagick недоступен, проверка остановится и покажет недостающие пути.

### 5. Добавить запись в `data/pages.json`

Пример статьи:

```json
{
  "id": "krm-2026-06-24",
  "type": "article",
  "title": "Кременная: транспорт и дороги в июне",
  "url": "/news/kremennaya/krm-2026-06-24/",
  "section": "kremennaya",
  "datePublished": "2026-06-24",
  "dateModified": "2026-06-24",
  "status": "confirmed",
  "excerpt": "Короткое описание для карточек и поиска.",
  "image": "/assets/img/news/kremennaya/krm-2026-06-24/cover.webp",
  "imageAlt": "Описание изображения",
  "topics": ["daily", "infrastructure"],
  "locations": ["Кременная", "ЛНР"],
  "sourceIds": []
}
```

Допустимые `type`: `article`, `guide`, `assessment`, `dossier`.

Допустимые `section`: `kremennaya`, `svo`, `lnr`, `law`, `civilian-impact`, `politics`, `assessment`, `warcrimes`.

Для памятки обязательны:

```json
"reviewedAt": "2026-06-24",
"reviewAfter": "2026-09-24",
"reviewStatus": "current"
```

Для содержательно обновлённого материала:

- сохраните исходную `datePublished`;
- измените `dateModified`;
- добавьте запись в `revisionHistory`;
- для крупной статьи или досье отразите изменение в видимом журнале обновлений.

### 6. Запустить единую проверку

```bash
npm run check
```

Команда автоматически:

- регистрирует внешние источники;
- сохраняет новый снимок карты, если геометрия изменилась;
- собирает главную, индексы, архив, поиск, JSON, sitemap и Atom;
- синхронизирует разделы, даты и JSON-LD;
- проверяет HTML, ссылки, изображения, даты, карту и метаданные;
- выполняет smoke-тесты архива, поиска и карты.

Любая ошибка должна завершить команду ненулевым кодом.

### 7. Проверить локально

```bash
npm run serve
```

Откройте `http://localhost:8000/` и проверьте:

- новую страницу;
- нужный индекс;
- `/archive/` и комбинации фильтров;
- `/search/`;
- мобильную ширину;
- отсутствие горизонтального переполнения.

### 8. Зафиксировать изменения

```bash
git add -A
git commit -m "feat: добавить материал о ..."
git push -u origin publish/kratkoe-nazvanie
```

Создайте Pull Request в `main`. Production-ветка — `main`; Cloudflare Pages публикует её на `krmrf.ru`.

### 9. Проверить production

После merge откройте:

- главную;
- новую публикацию;
- соответствующий раздел;
- архив;
- поиск;
- карту, если менялись её данные.

Проверьте мобильную версию и убедитесь, что версия в подвале соответствует релизу.

## Сохранение важного источника

`npm run check` добавляет внешние ссылки в `data/sources.json` и формирует очередь `data/source-preservation-queue.json`.

После законного сохранения файла источника выполните:

```bash
npm run source:capture -- src-xxxxxxxxxxxx /путь/к/файлу.pdf
```

Команда копирует файл в архив, рассчитывает SHA-256 и обновляет реестр. Подробности — в `SOURCES.md`.

## Обновление карты

Изменяйте только `data/zones.geojson`, включая:

- `updated`;
- `provenance.assessmentUrl`;
- описание уверенности и ограничения;
- `sourceIds`, если есть зарегистрированные ключевые источники.

`npm run check` автоматически создаст неизменяемый датированный снимок и обновит `/map/archive/`.

## Релизная копия

После крупного обновления:

```bash
npm run release
```

Команда повторно проверит проект, выполнит негативные тесты валидатора, создаст ZIP, `SHA256SUMS` и отдельный SHA-256 релизного архива.

## Откат

Если production сломан:

1. не исправляйте файлы прямо на Cloudflare;
2. найдите последний исправный commit или GitHub Release;
3. создайте отдельную ветку отката;
4. верните состояние через `git revert <commit>`;
5. выполните `npm run check`;
6. отправьте Pull Request в `main`;
7. после деплоя проверьте `krmrf.ru`.

Не используйте `git reset --force` для общей ветки.

## Команды

```bash
npm run images         # создать недостающие 480/960 WebP
npm run check          # полная сборка и проверка
npm run serve          # локальный сервер
npm run test:negative  # доказать, что валидатор ловит опасные ошибки
npm run release        # проверенный ZIP и контрольные суммы
npm run fixity         # проверить SHA256SUMS
```
