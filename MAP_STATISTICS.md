# Статистика карты KRM РФ

## Проверка полного ряда и районы карты — r24

При загрузке проверяются все соседние срезы, их порядок, IDs, даты, баланс добавлений/исключений и совпадение дневных и месячных сводок с полным рядом. Повреждённый или обрезанный JSON не заменяет проверенную статичную сводку; копирование остаётся доступным. Выбор дня охватывает весь архив, при этом таблица последних дней остаётся компактной.

Календарный день формируется из частей даты в МСК с григорианским календарём и латинскими цифрами. Строковое представление даты в мобильном браузере не меняет порядок срезов и принадлежность обновления к месяцу.

В `data/map-statistics-config.json` заданы три непересекающихся диагностических окна: Красный Лиман и окрестности, Волчанск и восточные окрестности, Орехов и восточные окрестности. Это условные географические границы, а не официальные границы военных направлений. Изменения вне окон относятся к «Остальным участкам», поэтому суммарные добавления и снятия согласованы с полной картой. Пересекающиеся окна, повторные ID и некорректные координаты блокируют сборку.

Для каждого последовательного обновления вычисляется точное пересечение добавленной и снятой российской геометрии с окнами тем же сферическим методом. Учтены все российские features, MultiPolygon, отверстия, перекрытия и повторные перекрасы. Дневная и месячная разбивка суммирует все обновления периода, а не только последнее снятие или изменение одного большого фрагмента. В архиве и исходных координатах правок нет; число +467,3 км² не заменяется ожидаемым знаком.

Публичный блок «По районам» закрыт по умолчанию и появляется только при изменениях в именованных районах. Текст для канала содержит их баланс. Общий итог относится ко всей карте. На доступных срезах 31 августа — 29 сентября 2026 года в выбранном лиманском окне снято 297,8 км² и добавлено 67,7 км², баланс −230,1 км². В волчанском окне баланс +157,9 км², в ореховском +100,6 км². Числа описывают опубликованную окраску; фактическую дату изменения контроля они не устанавливают.

Исходники клиентского JavaScript занимают менее 20 КБ; отдельный бюджет передаваемого gzip — 6 КБ. Дополнительная проверка ряда использует один форматтер дат и индекс обновлений по дням, чтобы не перебирать всю историю для каждого календарного дня. Новых зависимостей нет. Версия ассетов r24 предотвращает использование закэшированного старого клиента с новым блоком.

На `/map/#mapStatistics` под картой добавлен блок изменений площади. Он показывает добавления, исключения и чистое изменение российского контура по сохранённым срезам. В публичном блоке остаются последнее обновление, выбор дня и месяца, три показателя, кнопка «Скопировать для канала» и закрытые по умолчанию текст поста и таблицы. CSV, журнал импорта, предупреждения Git и технические пояснения из интерфейса убраны. Архив, JSON/CSV и проверки сохранены для расчётов и аудита.

## Как обновлять и получать пост

1. Измените `data/zones.geojson`; задайте новое, более позднее `updated`.
2. Добавьте согласованную запись в `data/map-changes.json`: `zonesUpdated`, `title`, `summary`, `details`. Укажите `kind`, если природа правки известна: `control`, `cartographic`, `mixed`, `review`. Без него сохраняется `unknown`; геометрия сама не устанавливает причину изменения.
3. Выполните `npm run build`. Сохранятся новый срез и рассчитанная сводка; вручную площади не вводятся.
4. Проверьте `npm run qa` в штатной среде проекта и страницу из `dist/`.
5. В статистике выберите период и нажмите «Скопировать для канала». Предварительно открывать текст не требуется. Полученный текст — редакционный черновик; публикация выполняется человеком.
6. Сохраните в commit изменения карты, новый журнал/файлы `data/map-archive/` и ожидаемые результаты сборки. `data/map-history/` и `dist/` в Git не сохраняются.

Локальный черновик последнего обновления:

```bash
npm run build
node tools/map-post.mjs --period=latest > map-post.txt
```

Другие варианты:

```bash
node tools/map-post.mjs --month=2026-10
node tools/map-post.mjs --period=7d
node tools/map-post.mjs --period=30d
node tools/map-post.mjs --period=all
npm run map:statistics
npm run test:map-statistics
npm run map:verify
```

`map:post` воспроизводимо проверяет исходные срезы, текущую геометрию, JSON/CSV и статичную сводку перед получением текста. Изменение контура без нового времени или устаревшая статистика блокируют генерацию. Для проверки всей геометрии/сводки используйте `map:verify`; перед публикацией новых данных выполняйте `build` и полный `qa`. Чтобы забрать только текст без заголовков npm, используйте показанный вызов `node`.

## Постоянная история

`data/map-archive/journal.json` содержит записи пригодных состояний (`versions`), сохранённых противоречивых вариантов (`ambiguousVersions`) и ссылки на неизменные GeoJSON с SHA-256. При сборке объединяются постоянный журнал, имеющийся кэш селектора, все доступные версии `data/zones.geojson` в истории текущего Git checkout и текущая карта. Старые Git-версии с одинаковым временем и разными геометриями/охватами группируются до расчёта: без независимо сохранённой публикации дата не входит в числовой ряд, все варианты остаются в архиве. Изменение уже сохранённой текущей карты без новой даты по-прежнему блокирует запись. Возврат A → B → A сохраняется как три состояния. Проверка без изменения геометрии с новым временем тоже сохраняется и может давать настоящий ноль.

В селекторе карты остаются последние 24 состояния (настройка `KRM_MAP_HISTORY_LIMIT`, 2–48). Этот лимит не обрезает постоянный журнал и статистику. Последовательные одинаковые геометрии могут не дублироваться в селекторе; в постоянном журнале они остаются. После изменения охвата для нового среза используйте новое значение `statistics.scopeVersion` и согласованное описание конфигурации; сравнение разных версий охвата даёт пропуск, а не ложный прирост.

Сборка без `.git` воспроизводится из постоянного архива. Workflow используют `fetch-depth: 0`; при shallow-копии сохраняется предупреждение о неполной Git-истории. Недатированные/неразбираемые старые версии Git перечисляются как неимпортированные, без выдуманных дат. Непригодная старая геометрия не считается нулевым состоянием и описывается в журнале исключений; повреждение текущей карты или сохранённых архивных файлов останавливает сборку. Новые записи из локальной сборки следует сохранять вместе с картой: пересоздание истории только в CI не гарантирует сохранение промежуточных состояний после squash/rebase.

Импорт дополнительного исходного среза:

```bash
node tools/map-history.mjs --import=/absolute/path/old-zones.geojson
npm run build
```

У GeoJSON должно быть корректное `updated`, которое не позднее текущей опубликованной карты. Прошлое не надо заменять сегодняшним временем: это изменило бы хронологию. Более старый текущий файл поверх нового архива блокируется; редакционный возврат геометрии оформляется новым временем.

## Что измеряется

Метод `krmrf-spherical-sweep-v1` фиксирован. Измеряется объединение Polygon/MultiPolygon с именами слоя `russian`, `rf`, `россия`, `рф`; отверстия вычитаются, перекрытия считаются один раз.

Для соседних состояний A и B отдельно измеряются B\A (добавлено) и A\B (исключено). Итог = площадь B − площадь A; он проверяется против добавлено − исключено. Для нескольких обновлений добавления/исключения суммируются по соседним сравнениям: участок, меняющийся повторно, может попасть в сумму несколько раз. Итог за период остаётся разностью конечной и начальной площади. Поэтому нулевой итог не доказывает отсутствия изменений.

Расчёт использует вертикальное разбиение границ, сферу радиуса 6 371 008,8 м и аналитический интеграл `R² · ∫(sin φверх − sin φниз) dλ`. Рёбра в этой модели линейны в координатах долготы/широты. Ориентации проверяются целочисленными предикатами; внутри вычисления координаты округляются до 10⁻¹⁰ градуса. Исходные файлы и визуальный контур не упрощаются. Значение модельное: другой радиус/эллипсоид/интерполяция могут дать другие числа; пересчитывать часть ряда другим методом нельзя.

Самопересечения, незамкнутые/пустые кольца, некорректные отверстия, неподходящие координаты, антимеридиан и широты вне ±85° не исправляются молча. Ошибка вычисления останавливает сборку. Отсутствие российского слоя не трактуется как нулевая площадь контроля. Контрольные суммы и геометрия каждого среза проверяются; `map:verify` заново воспроизводит JSON, CSV и статичную сводку.

На экране числа округляются до 0,1 км²; малые значимые ненулевые значения обозначаются `<0,1`. Показатели округляются независимо, итог вычисляется до округления: видимое «добавлено − исключено» может отличаться от показанного итога на 0,1 км². В JSON/CSV остаются неокруглённые модельные результаты. Округление не означает точность оценки реального контроля до 0,1 км².

## Дни, месяцы и пределы выводов

- Дата числа — дата публикации конечного среза, не дата боевого события. Все времена отображаются как МСК; старые отметки без часового пояса приняты за UTC+03:00. Если это предположение неверно, требуется отдельная миграция дат всей истории.
- Старые отметки вида `2026-05-18 8:08` разбираются как `2026-05-18 08:08` МСК. Исходное `updated` и геометрия сохраняются без изменения. Минуты, календарная дата и диапазон часов проверяются строго; отсутствующая дата не восстанавливается из времени commit. Ранее пропущенная пригодная Git-ревизия импортируется при сборке и удаляется из текущего списка исключений.
- День без среза = `no_snapshot` и пустые числовые поля, а не 0 км² и не «фронт не менялся». Публичная дневная таблица показывает только дни публикаций и известных непригодных состояний за последние 30 календарных дней до последнего среза; пустые и будущие дни не достраиваются. В данных пропуски остаются пропусками. Исходная запись без предыдущего среза — `baseline`.
- Изменение между 3 и 8 октября не распределяется искусственно по пяти дням. В таблице 8 октября указан весь интервал 3 → 8 октября.
- Месячная сводка группирует обновления по дате конечного среза. Интервал 26 сентября → 3 октября входит в опубликованные октябрьские обновления и явно помечен пересечением границы месяца. Это не установленная площадь перехода за календарный октябрь. Для отделения событий по месяцам нужен промежуточный срез.
- Если начало периода не покрыто, показывается доступная часть. Для 7/30 дней до последнего среза может понадобиться исходное опубликованное состояние раньше начала окна; обе фактические даты и предупреждение выводятся в посте CLI. Эти режимы убраны из публичного интерфейса.
- Текущий слой измеряется целиком, без маски Украины и без отдельного слоя ВСУ. Его общая площадь не является показателем «площадь Украины под контролем РФ». Уменьшение зоны РФ не доказывает прирост контроля ВСУ: возможны неопределённая зона, исправление контура или другие причины.
- `kind=cartographic` учитывается в числах и обозначается в тексте. При `unknown` причину изменения не устанавливаем. Наличие новых цифр не заменяет независимой проверки редакционного описания.

## Доставка данных и проверки

Расчёт выполняется при сборке; клиент получает компактные готовые данные. Сборка создаёт статичную сводку, которая читается без JavaScript. JSON/CSV и HTML получают согласованный ключ версии; данные другой версии не подменяют текущую сводку. При ошибке/тайм-ауте загрузки выбор периода отключается, сохранённая сводка остаётся доступной. При отказе Clipboard API блок текста автоматически открывается, текст выделяется для ручного копирования. Кнопка доступна и при ошибке загрузки JSON: копируется сохранённый текст именно этой версии страницы.

Экспорт публикует статистику, постоянный журнал и геометрии; служебные настройки и инструменты в публичную сборку не включаются. Клиентская статистика имеет отдельные бюджеты JS 12 КБ, CSS 3 КБ; исходные бюджеты остальных файлов сохранены, JSON ограничен 5 МБ.

Тесты покрывают аналитические площади, пересечения, отверстия, острова, дубликаты, порядок колец, повреждения, баланс, A → B → A, пропуски, полночь/месяц/часовой пояс, полный Git сверх лимита селектора, миграцию кэша, повторяемость, клиентский выбор, сбой сети, смешение версий и копирование. Двенадцать Playwright-сценариев проверяют компактный интерфейс, выбор дня/месяца, копирование и его резервный вариант, сбой загрузки, ширины 320/360/390/430 пикселей и статичную сводку без JavaScript. Общий браузерный контракт проекта также проверяет всю страницу карты.

## Исправление импорта истории от 11 октября 2026 года

Сборка различает три ситуации: коммит без файла карты, непригодный старый срез и ошибка чтения Git. Коммит без файла не является нулевой картой. Старый GeoJSON без даты, распознанного слоя РФ или корректной геометрии не включается в расчёт; его полный commit, дата (когда установлена), SHA-256 прочитанного содержимого, названия слоёв и причина сохраняются в `skippedRevisions` постоянного журнала. Неизвестные имена слоёв не переименовываются автоматически. Поле `kind=absent` означает отсутствие файла в коммите, `kind=unusable` — прочитанный, но непригодный для расчёта GeoJSON.

В дневной таблице известная дата исключённого среза внутри доступного ряда помечается «Нет сопоставимых данных»; числовые поля остаются пустыми. Если исключённое состояние лежит между двумя пригодными срезами, сравнение их контуров остаётся доступным, но интерфейс и черновик поста предупреждают, что промежуточные добавления и исключения полностью не восстановлены. Несколько непригодных ревизий одного времени считаются одной пропущенной датой среза; если для этого времени есть пригодное состояние, пропуска даты нет. Журнал ревизий сохраняет каждое исключение отдельно.

Удалённый или недоступный Git-объект, ошибка чтения дерева/истории, существующий пустой файл карты, изменение уже сохранённой текущей карты без новой даты, повреждённая текущая карта, явный импорт или постоянный архив останавливают сборку. Противоречивые старые Git-версии обрабатываются отдельно, как описано ниже. Данные не подменяются нулями. Перед созданием новых архивных файлов проверяются все неизменные пути. Штатная конфигурация времени — МСК (`Europe/Moscow`, старое время без пояса `+03:00`); изменение этих правил требует явной миграции.

Старое повреждённое описание `map-changes.json` не удаляет пригодную геометрию: неподдерживаемые поля не используются, причина остаётся `unknown` и выводится предупреждение. Текущее редакционное описание и метаданные постоянного архива проверяются строго. Пригодность исторической геометрии проверяется до группировки; конфликт дат сохраняется в отдельном архиве и не выдаётся за неподдерживаемый формат.

Импортируется вся доступная история файла, достижимая из `HEAD` текущей ветки, включая слитые ветки (`git log --full-history`). Экспериментальные несоединённые ветки автоматически не импортируются. `gitMode=shallow` явно показывает неполный clone, `unavailable` — отсутствие Git, `available-head-ancestry` — доступную историю текущей ветки; последнее не доказывает полноту всех когда-либо опубликованных версий сайта. Уже сохранённый архив сохраняется при сокращении истории clone. Отсутствующий Git у ZIP-копии допускается; неисправный имеющийся репозиторий не считается отсутствием Git.

Дополнительные регрессионные проверки запускаются командой `npm run test:map-history` и включены в `npm run qa`. Они создают собственные временные Git-репозитории; объекты и данные основного проекта не изменяют.

## Противоречивые даты: дополнительное исправление 11 октября 2026 года

В старом Git несколько разных корректных карт могут иметь одно `updated`, например `2026-03-13T05:50:00.000Z`. Это время не устанавливает порядок публикации. Сборка не выбирает первый/последний Git-коммит, не подменяет дату временем commit и не разносит варианты по выдуманным минутам.

- Для каждой даты сравнивается пара «хеш геометрии + версия охвата». Одинаковая пара в нескольких коммитах не является противоречием, даже если форматирование JSON различается.
- Без независимого подтверждения все разные варианты даты сохраняются в `ambiguousVersions` и исключаются из `versions`/сравнений. GeoJSON хранится в обычном постоянном архиве без изменения геометрии и данных; сериализация JSON нормализована. Записи содержат дату, охват, SHA-256, хеш геометрии и происхождение. Для соответствующих Git-коммитов `skippedRevisions.kind=ambiguous` содержит полный commit, SHA-256 исходного содержимого Git, ссылку на сохранённый вариант, число вариантов и `resolution=unresolved`.
- Ранее сохранённая текущая карта (`published-map`), исходное состояние из загруженного архива с SHA-256 в `sourceRefs` (`archive:...@sha256:...`) и явный редакционный импорт (`import:...`) устанавливают конкретный срез. Он остаётся в `versions`, альтернативы сохраняются в `ambiguousVersions`, а исключённые ревизии отмечаются `resolution=anchored`. Это не восстановление остальных промежуточных публикаций и не доказательство боевых событий. Пометки происхождения — часть проверяемого журнала; не присваивайте их предполагаемым данным вручную.
- Сам факт ранее выполненного импорта из Git или наличие среза в кэше селектора не подтверждает, какой вариант публиковался. Если после fetch найден второй контур того же времени, ранее импортированный Git-срез переводится в `ambiguousVersions` вместе с новым вариантом. Его файл и происхождение сохраняются. Неопределённость сохраняется при последующих shallow-сборках и работе без Git.
- Спорная дата считается один раз в `omittedSnapshotCount`, сколько бы ревизий ни было. День с неизвестным состоянием получает `unavailable` и пустые числовые поля. Календарь включает известные непригодные/спорные даты даже раньше первого пригодного среза, вплоть до текущей карты. Месячная таблица показывает дни с неполными данными. Месяц без двух сопоставимых срезов не получает числовую оценку.
- Между двумя пригодными срезами через спорную дату можно сравнить конечные контуры. Дневная сводка относит результат ко всему фактическому интервалу; интерфейс, CSV и пост предупреждают, что промежуточные добавления/исключения восстановлены не полностью. Результат не распределяется по пропущенным дням.

Разрешайте спорную дату только при наличии самостоятельно проверенного исходного опубликованного состояния: используйте явный `--import` этого GeoJSON. Это редакционный выбор, который записывается в происхождение; альтернативный вариант не удаляется. Перед получением поста выполните `npm run build`. Контрольные суммы спорных файлов проверяют как импорт истории, так и генератор статистики/поста.

Нельзя исправлять эту ошибку массовой заменой `updated` старых файлов или удалением постоянного архива. Для установки дополнительного патча поверх предыдущего исправления используется обычный `git apply --check`, затем `git apply` и штатный `npm run qa`.

## Компактный интерфейс и мобильная версия

Периоды публичного блока: последнее обновление, день публикации карты и месяц публикаций. День объединяет все сопоставимые обновления с конечной датой в выбранном дне по МСК; многодневный интервал не делится на вымышленные суточные изменения. Для дня без сопоставимых состояний показывается «нет данных», а не ноль. Месяцы без опубликованных сопоставимых изменений и без известных проблемных состояний не заполняют список пустыми строками.

Даты, суммы и короткий текст поста формирует общее ядро на сервере сборки и в браузере. В посте остаются период, три числа, ссылка на карту и необходимые условные оговорки о неполном периоде, переходе месяца, пропусках и правках контура. Данные о контроле ВСУ не выводятся как измеренная площадь. Числа и геометрическая методика не меняются.

На экранах до 680 px показатели и строки таблиц перестраиваются в вертикальные записи. Селекторы имеют шрифт 16 px и высоту не менее 46 px, кнопка — 48 px и полную ширину. Текст и таблицы закрыты по умолчанию; копирование находится перед ними. В тестах проверяются ширины 320, 360, 390 и 430 px, выбор дня/месяца, буфер обмена, отказ загрузки, несовпадение версии данных и ручное копирование при отказе Clipboard API.
