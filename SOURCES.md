clear# Источники KRM РФ: зачем нужны, как работают и что сохраняют

Этот документ объясняет систему источников простыми словами.

## 1. Зачем нужны источники

Источники нужны не для красоты и не для отдельного раздела сайта. Они нужны для доказательной дисциплины архива.

Система источников отвечает на вопросы:

```text
откуда взята ссылка
в какой публикации она используется
важная она или обычная
есть ли сохранённая копия
если внешний сайт исчезнет, останется ли доказательство
не сломалась ли связь между статьёй и источником
```

Для KRM РФ это важно, потому что сайт должен быть не просто лентой материалов, а долговечным архивом.

## 2. Какие файлы отвечают за источники

```text
data/sources.json                         реестр всех внешних источников
data/source-preservation-queue.json       очередь важных источников для сохранения
data/sources.schema.json                  схема проверки источников
data/pages.json                           публикации и их sourceIds
SOURCES.md                                эта инструкция
tools/sources.mjs                         автоматическая синхронизация источников
tools/source-capture.mjs                  сохранение локальной копии источника
tools/validate.mjs                        проверка связей и SHA-256
```

## 3. Что сейчас делает `npm run check`

В составе `npm run check` запускается:

```bash
npm run sources:sync
```

Эта команда выполняет `tools/sources.mjs`.

Скрипт:

1. читает `data/pages.json`;
2. открывает HTML каждой публикации;
3. ищет внешние ссылки внутри `<main>`;
4. игнорирует внутренние ссылки на `krmrf.ru`;
5. добавляет внешние ссылки в `data/sources.json`;
6. обновляет `sourceIds` в `data/pages.json`;
7. формирует `data/source-preservation-queue.json` для важных несохранённых источников.

## 4. Важное правило

Не нужно придумывать `sourceIds` вручную.

Правильная логика такая:

```text
добавил внешнюю ссылку в HTML публикации
        ↓
npm run check
        ↓
ссылка появилась в data/sources.json
        ↓
id источника появился в sourceIds этой публикации
```

Если поставить `sourceIds` вручную, но ссылки нет в основном HTML-тексте, проверка может показать предупреждение или рассинхронизацию.

## 5. Пример источника в HTML

В статье лучше иметь блок:

```html
<section class="note-box">
  <h2>Источники и ограничения</h2>
  <p>
    Материал основан на сообщениях жителей и
    <a href="https://example.com/source">официальном сообщении</a>.
    Отдельные сведения требуют дополнительной проверки.
  </p>
</section>
```

После `npm run check` ссылка попадёт в реестр.

## 6. Что хранится в `data/sources.json`

Пример записи:

```json
{
  "id": "src-044455c699ee",
  "url": "https://example.com/source",
  "title": "Название источника",
  "publisher": "example.com",
  "registeredAt": "2026-06-24",
  "accessedAt": null,
  "archiveUrl": null,
  "localCopy": null,
  "sha256": null,
  "status": "referenced",
  "notes": "Источник зарегистрирован автоматически по ссылке в публикации.",
  "preservationPriority": "normal",
  "referencedBy": ["page-id"]
}
```

Поля означают:

- `id` — внутренний номер источника;
- `url` — исходная ссылка;
- `title` — текст ссылки или название источника;
- `publisher` — домен сайта;
- `registeredAt` — когда источник попал в реестр;
- `accessedAt` — когда источник был сохранён или проверен;
- `archiveUrl` — точная архивная ссылка, если есть;
- `localCopy` — путь к локальной копии внутри сайта;
- `sha256` — контрольная сумма локальной копии;
- `status` — состояние источника;
- `preservationPriority` — важность сохранения;
- `referencedBy` — какие публикации ссылаются на источник.

## 7. Статусы источников

```text
referenced     ссылка зарегистрирована, но копия не сохранена
preserved      есть локальная копия или архивная фиксация
unavailable    источник стал недоступен
```

Сам факт наличия ссылки не означает, что утверждение полностью доказано. Источник нужно оценивать по содержанию, происхождению и контексту.

## 8. Очередь сохранения источников

Файл:

```text
data/source-preservation-queue.json
```

Это список источников, которые желательно сохранить первыми.

Туда попадают важные источники, если у них нет `localCopy` и `archiveUrl`.

Приоритеты:

```text
high      досье и оценки фронта
medium    памятки
normal    обычные статьи
```

Обычные `normal`-источники в очередь обычно не попадают.

## 9. Что источники НЕ делают автоматически

Система источников не делает этого:

- не скачивает все сайты сама;
- не сохраняет PDF сама;
- не делает скриншоты сама;
- не проверяет истинность источника сама;
- не заменяет редакционный блок “Источники и ограничения”;
- не делает материал юридически безупречным сама по себе.

Она делает другое:

- фиксирует ссылки;
- связывает источники с публикациями;
- показывает, что надо сохранить;
- проверяет сохранённые копии;
- считает SHA-256 локальных файлов.

## 10. Как сохранить локальную копию источника

Допустим, в очереди есть источник:

```text
src-xxxxxxxxxxxx
```

Ты скачал или получил допустимый файл источника:

```text
tmp/document.pdf
```

Команда:

```bash
npm run source:capture -- src-xxxxxxxxxxxx tmp/document.pdf
```

Если есть точная архивная ссылка:

```bash
npm run source:capture -- src-xxxxxxxxxxxx tmp/document.pdf https://archive.example.com/source
```

Скрипт:

- копирует файл в `data/sources/files/<source-id>/`;
- записывает `accessedAt`;
- записывает `localCopy`;
- считает `sha256`;
- меняет `status` на `preserved`;
- при наличии третьего аргумента записывает `archiveUrl`.

После этого обязательно:

```bash
npm run check
```

## 11. Где будут лежать локальные копии

```text
data/sources/files/src-xxxxxxxxxxxx/document.pdf
```

Пока локальных копий нет, эта папка может отсутствовать.

Удалять её нельзя, если там уже сохранены источники: проверка начнёт ругаться на отсутствующие файлы или несовпадение SHA-256.

## 12. Сколько места это займёт

Текущий реестр ссылок занимает мало места: десятки килобайт.

Место начнёт расти только после сохранения локальных копий.

Примерно:

| Тип источника | Размер |
|---|---:|
| HTML-страница | 50–500 КБ |
| PDF постановления | 200 КБ – 5 МБ |
| большой PDF | 5–30 МБ |
| скриншот | 300 КБ – 3 МБ |
| фото | 300 КБ – 5 МБ |
| видео | 10 МБ – сотни МБ |

Практический ориентир:

```text
30 важных PDF/HTML-источников = примерно 30–300 МБ
100 источников = примерно 100 МБ – 1 ГБ
видео быстро превращают архив в десятки гигабайт
```

Совет: в GitHub хранить PDF, HTML, скриншоты и документы; тяжёлые видео хранить отдельно на физическом носителе или в отдельном архиве, а в сайте фиксировать ссылку, описание, ключевые кадры и хэш, если возможно.

## 13. Что сохранять обязательно

В первую очередь сохранять:

- постановления;
- PDF-документы;
- нормативные акты;
- официальные сообщения;
- документы по выплатам;
- документы по жилью;
- источники для досье;
- источники по погибшим и пострадавшим;
- источники для оценок фронта;
- материалы, исчезновение которых разрушит доказательную цепочку.

## 14. Что можно не сохранять сразу

Можно отложить:

- обычные новостные ссылки;
- повторяющиеся публикации;
- малозначимые источники;
- ссылки, которые легко найти в нескольких местах.

## 15. Что лучше не хранить в публичном репозитории

Не хранить без крайней необходимости:

- тяжёлые видео;
- большие архивы;
- материалы с личными данными;
- чужие полные статьи, если есть риск нарушения прав;
- материалы, нарушающие приватность или достоинство пострадавших.

Для таких случаев лучше:

- указать точный URL;
- указать архивный URL;
- дать библиографическое описание;
- сохранить короткий допустимый фрагмент;
- хранить полную копию вне публичного репозитория.

## 16. Источники для разных типов материалов

### Обычная статья по Кременной

Достаточно:

- 1–3 внешние ссылки, если они есть;
- блок “Источники и ограничения”;
- осторожные формулировки.

Если материал основан на сообщениях жителей и внешних ссылок нет, прямо написать:

```text
Материал основан на сообщениях местных жителей. Отдельные эпизоды требуют дополнительной проверки. По мере появления официальных данных материал может быть обновлён.
```

### Оценка фронта

Для оценки фронта источники важны. Желательно иметь:

- официальные сводки;
- карту/предыдущую оценку;
- сообщения по направлениям;
- методологические ограничения;
- ссылки на данные, если они используются.

### Памятка

Для памятки источники обязательны:

- постановление;
- указ;
- страница ведомства;
- PDF;
- форма обращения;
- официальный портал.

Ключевые PDF лучше сохранять локально через `source:capture`.

### Досье

Досье — самый строгий формат.

Желательно:

- несколько независимых источников;
- официальные сообщения;
- фото/видео/документы;
- дата доступа;
- сохранённая копия или точный архивный URL;
- объяснение, что подтверждает каждый источник;
- блок “Что требует проверки”.

## 17. Как посмотреть очередь источников

```bash
cat data/source-preservation-queue.json
```

Удобнее:

```bash
node -e "const q=require('./data/source-preservation-queue.json'); for (const x of q) console.log(x.priority, x.sourceId, x.title)"
```

## 18. Что делать прямо сейчас

Не нужно сразу сохранять все источники.

Рабочий порядок:

1. Все новые материалы делать с блоком “Источники и ограничения”.
2. Важные внешние ссылки ставить прямо в HTML.
3. Запускать `npm run check`.
4. Сначала сохранять источники с приоритетом `high`.
5. Потом `medium`.
6. `normal` сохранять только при необходимости.

## 19. Короткая схема

```text
ссылка в HTML
        ↓
npm run check
        ↓
data/sources.json
        ↓
sourceIds в data/pages.json
        ↓
data/source-preservation-queue.json
        ↓
npm run source:capture
        ↓
localCopy + sha256 + status preserved
```
