# Техническая заморозка KRM РФ

Период: с выпуска `2026.7.29-r12` до 29 июля 2027 года.

Цель — минимум год заниматься содержанием, редактурой и статистикой, не переделывая платформу. Node.js 24 LTS выбран как поддерживаемая линия на весь срок заморозки; после этой даты нужен один плановый технический осмотр, а не новая архитектура.

## Что разрешено

- добавлять и редактировать публикации;
- обновлять `data/pages.json` и после осознанной правки выполнять `npm run content:lock`;
- обновлять карту через `data/zones.geojson` и `data/map-changes.json`;
- заменять изображения публикаций;
- исправлять подтверждённую поломку, уязвимость или изменение требований GitHub Pages;
- улучшать заголовок, описание и внутренние ссылки страницы по данным статистики;
- обновлять зависимости только при исправлении безопасности или несовместимости CI.

## Что заморожено

- переход на CMS, Astro, Hugo или другой генератор;
- Atom/RSS и дополнительные форматы выдачи;
- новые клиентские фреймворки;
- новые продуктовые разделы и сложные фильтры;
- история карт и отдельная система сохранения источников;
- переделка URL, навигации, темы и структуры данных;
- добавление новых счётчиков и экспериментальных виджетов;
- замена рабочего Pages workflow без внешней необходимости.

## Обычный выпуск материала

```bash
npm run images
npm run build
npm run content:lock
npm run qa
PORT=8080 npm run serve:dist
```

После просмотра публикации, главной, нужного раздела, архива, поиска и мобильной версии можно делать commit, push и merge в `main`. Публикацию выполняет GitHub Actions только из `dist`.

## Техническое исключение

Перед изменением замороженной части нужно письменно зафиксировать:

1. какая реальная поломка, уязвимость или внешнее требование возникло;
2. почему редакционным способом её не решить;
3. какой минимальный патч нужен;
4. какая автоматическая проверка не даст дефекту вернуться.

Если этих четырёх пунктов нет, техническую часть не менять.

## Исключение от 30 августа 2026 года: подтверждённые расхождения публикаций

1. **Поломки.** Единственная оценка использовала article-nav без CSS; отсутствовали
   переходы к опубликованным соседям, семь памяток имели двойные крошки, четыре
   материала Кременной потеряли container--content. Служебные блоки зависели от
   тега метаданных, CSS перекрывал их отступы. Поиск архива сохранял старую выдачу
   после сокращения запроса, а отдельный поиск скрывал совпадения после пятидесяти.
2. **Почему недостаточно редактуры.** Текст публикаций верен для целей этого
   технического исправления и не должен сокращаться или переписываться. Ошибки
   находятся в повторяемой разметке, вставках сборки и обработчиках интерфейса.
3. **Минимальная область.** Существующая сборка нормализует служебный каркас по
   правилам PUBLICATION_LAYOUT.md, сохраняя содержимое и особенности типов.
   Исправляются размеры responsive-подсказок, CSS-каскад и две поисковые обёртки.
   Платформа, зависимости, URL, данные карты, форматы данных и Pages workflow
   остаются прежними. Меняется только техническая версия для cache busting.
4. **Защита от возврата.** В validate добавлены проверки всех публикаций и общих
   оболочек; test:uniformity покрывает поисковые состояния и нормализацию;
   негативные и штатные браузерные тесты дополнены сценариями этих ошибок.
   До обновления content-integrity отдельно сверены все редакционные тексты,
   ссылки, подписи и изображения с исходным архивом. Контроль содержания не ослаблен.

## Исключение от 28 августа 2026 года: бюджет поискового индекса

1. **Подтверждённая остановка выпуска.** После добавления 76-й публикации
   `data/search-index.json` вырос с 515 189 до 524 452 байт. Проверка
   производительности останавливает `npm run qa` на прежнем лимите 520 000 байт.
   Размер того же индекса в gzip уровня 9 — 117 174 байта, ниже лимита 150 000.
2. **Почему не редакционная правка.** Индекс уже записывается компактным JSON;
   для каждой публикации повторяющиеся поисковые слова исключаются. Рост
   связан с добавлением материала. Сокращать его ради прежнего общего лимита
   означало бы менять содержание по причине, не связанной с редактурой.
3. **Минимальное изменение.** Бюджет несжатого индекса повышается до 600 000
   байт. Бюджет gzip остаётся 150 000 байт. Формат v2, алгоритм поиска,
   публикации, изображения и остальные ограничения не изменяются.
4. **Проверка.** `npm run test:performance` продолжает проверять оба предела;
   перед выпуском обязателен полный `npm run qa`. При подготовке патча отдельно
   проверены индекс размером 524 452 байта, граница 600 000 байт, превышение
   этой границы на один байт и превышение gzip-бюджета при допустимом raw-размере.

## Исключение от 29 сентября 2026 года: состояние исторической карты

1. **Воспроизведённые ошибки.** После успешного просмотра одного среза и ошибки
   загрузки другого геометрия возвращалась к текущей, но пояснение и URL сохраняли
   прежний срез. Во время следующей загрузки сравнение оставалось доступным и могло
   использовать прежнюю геометрию под новой выбранной датой.
2. **Почему не редакционная правка.** Причина в асинхронном состоянии `map.js`,
   а не в текстах, датах публикаций или данных карты.
3. **Минимальный патч.** При загрузке сбрасывается геометрия для сравнения и
   скрывается кнопка. При отказе подпись и URL согласуются с текущей геометрией.
   Движок карты, поставщики подложки, CSS, URL маршрутов и зависимости сохранены.
4. **Защита от возврата.** `npm run test:map-state` выполняет четыре сценария
   на реальном клиентском скрипте с моделью DOM, сети и Leaflet. Два сценария
   воспроизводят исходные ошибки; два проверяют запоздалые ответы. Команда включена
   в `qa`. Это проверка состояния, не замена браузерной проверки карты.

## Исключение от 29 сентября 2026 года: подписи SVG-хронологии

1. В статье `news/civilian-impact/bpla-lnr-2026-09-08/index.html` первая длинная
   подпись SVG выходит за `viewBox` 760 × 420, а дата «4 сентября» соприкасается
   с текстом. Это воспроизведено рендером librsvg/Cairo с sans-serif.
2. Это ошибка размещения подписи, а не редакционного содержания.
3. Текстовые подписи сдвинуты на 20 единиц; первая разбита на два `tspan`.
   Слова, даты, графика, размер `viewBox`, URL и метаданные не изменены.
4. Рендер до/после просмотрен; исходный `content:check` проходит без перезаписи
   манифеста. Браузерная проверка мобильной читаемости остаётся отдельным условием.
