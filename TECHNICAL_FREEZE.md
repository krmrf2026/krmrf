# Техническая заморозка KRM РФ

Период: с выпуска `2026.7.29-r12` до 29 июля 2027 года.

Цель — минимум год заниматься содержанием, редактурой и статистикой, не переделывая платформу. Node.js 24 LTS выбран как поддерживаемая линия на весь срок заморозки; после этой даты нужен один плановый технический осмотр, а не новая архитектура.

## Что разрешено

- добавлять и редактировать публикации;
- обновлять `data/pages.json` и после осознанной правки выполнять `npm run content:lock`;
- обновлять карту через `data/zones.geojson` и `data/map-changes.json`;
- заменять изображения публикаций;
- исправлять подтверждённую поломку, уязвимость или изменение требований GitHub Pages;
- улучшать заголовок, описание и внутренние ссылки страницы по данным статистики;
- обновлять зависимости только при исправлении безопасности или несовместимости CI.

## Что заморожено

- переход на CMS, Astro, Hugo или другой генератор;
- Atom/RSS и дополнительные форматы выдачи;
- новые клиентские фреймворки;
- новые продуктовые разделы и сложные фильтры;
- история карт и отдельная система сохранения источников;
- переделка URL, навигации, темы и структуры данных;
- добавление новых счётчиков и экспериментальных виджетов;
- замена рабочего Pages workflow без внешней необходимости.

## Обычный выпуск материала

```bash
npm run content:lock
npm run qa
PORT=8080 npm run serve:dist
```

После просмотра публикации, главной, нужного раздела, архива, поиска и мобильной версии можно делать commit, push и merge в `main`. Публикацию выполняет GitHub Actions только из `dist`.

## Техническое исключение

Перед изменением замороженной части нужно письменно зафиксировать:

1. какая реальная поломка, уязвимость или внешнее требование возникло;
2. почему редакционным способом её не решить;
3. какой минимальный патч нужен;
4. какая автоматическая проверка не даст дефекту вернуться.

Если этих четырёх пунктов нет, техническую часть не менять.

## Исключение от 28 августа 2026 года: бюджет поискового индекса

1. **Подтверждённая остановка выпуска.** После добавления 76-й публикации
   `data/search-index.json` вырос с 515 189 до 524 452 байт. Проверка
   производительности останавливает `npm run qa` на прежнем лимите 520 000 байт.
   Размер того же индекса в gzip уровня 9 — 117 174 байта, ниже лимита 150 000.
2. **Почему не редакционная правка.** Индекс уже записывается компактным JSON;
   для каждой публикации повторяющиеся поисковые слова исключаются. Рост
   связан с добавлением материала. Сокращать его ради прежнего общего лимита
   означало бы менять содержание по причине, не связанной с редактурой.
3. **Минимальное изменение.** Бюджет несжатого индекса повышается до 600 000
   байт. Бюджет gzip остаётся 150 000 байт. Формат v2, алгоритм поиска,
   публикации, изображения и остальные ограничения не изменяются.
4. **Проверка.** `npm run test:performance` продолжает проверять оба предела;
   перед выпуском обязателен полный `npm run qa`. При подготовке патча отдельно
   проверены индекс размером 524 452 байта, граница 600 000 байт, превышение
   этой границы на один байт и превышение gzip-бюджета при допустимом raw-размере.
