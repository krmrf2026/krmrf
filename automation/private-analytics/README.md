# Приватная аналитика KRM РФ

Комплект предназначен для отдельного приватного Git-репозитория. В публичном сайте workflow не запускается. Приватность проверяется перед API. Порядок подключения — в `METRIKA_SETUP.md` сайта: OAuth `metrika:read`, secret `METRIKA_OAUTH_TOKEN`, счётчик 110383043, девять точных JavaScript-целей, первый Run workflow и сверка с интерфейсом.

Скопируйте Python-файлы и README в корень приватного репозитория, `analytics.yml` — в `.github/workflows/analytics.yml`. Включите Issues и Actions; разрешения contents/Issues указаны в YAML. Включите GitHub notifications об ошибках Actions и недельных Issues.

Python 3.12+, внешних библиотек нет. Проверка: `python3 -m unittest -v test_exporter.py`. Для локального запуска токен передайте окружением, не аргументом:

```bash
read -rsp 'OAuth: ' METRIKA_OAUTH_TOKEN
echo
export METRIKA_OAUTH_TOKEN
export METRIKA_COUNTER_ID=110383043
python3 collect_metrika.py --lookback 7 --extended
unset METRIKA_OAUTH_TOKEN
```

Для первой загрузки истории можно выбрать `--lookback 90 --extended`. Запускайте из приватной копии, не из корня публичного сайта. `--end=YYYY-MM-DD` повторяет прошлый закрытый период.

Ежедневно повторно запрашиваются семь законченных московских суток; последние три предварительные. Ключ файла — дата: дубликатов суток нет. Каждый день заменяется атомарно после получения всех его таблиц. Дневные уникальные пользователи не складываются: пользователи за неделю/28/90 дней получаются отдельными запросами. По понедельникам создаются дополнительные сравнения 28/28,90/90 и обновляемое приватное Issue.

Сохраняются агрегаты: посещаемость, источники, поисковые системы, первые/повторные визиты, страницы входа/выхода, устройства, страны, UTM и цели. ClientID, IP, сырые события, поисковые фразы и полные URL с query не выгружаются. Цель в таблице входов относится к визиту в целом, не обязательно к посадочной статье. Эти таблицы не дают точных когорт или полного маршрута между страницами.

Пагинация, семплирование, schema и конечные числа проверяются. 429/5xx/сетевые отказы повторяются до пяти раз; 401/403 немедленно останавливают загрузку с сохранением прежних файлов. Отсутствующая цель — null/предупреждение, неверный тип цели или неоднозначность — ошибка. Правило MAD использует завершённый день с задержкой три дня и минимум шесть прошлых одноимённых дней недели. Это эвристика, не доказательство причины.

Сверяйте итог одного дня/недели с интерфейсом при тех же датах, МСК, атрибуции и сегментах. При Access failure обновите доступ/secret и повторите запуск. При sampling/изменении таблицы не подменяйте результат нулями. История сохраняется в приватном Git. Для публичной сводки позже нужна отдельная обезличенная выборка с подавлением малых групп.

Проверяйте свежесть `data/health.json`. Workflow не способен сообщить, что сам вообще не запустился: для строгого независимого контроля нужен внешний наблюдатель с порогом 36 часов; он не развёрнут этим комплектом. Cron GitHub может задерживаться, мгновенная статистика не обещается.
