# Существующие шаблоны публикаций: единые правила

Технический патч `2026.8.30-r18` сохраняет платформу, адреса, тексты, изображения,
метаданные каталога, оформление рубрик и действующий GitHub Pages workflow.
Нормализация работает в существующем `npm run build`, без клиентского шаблонизатора
и без новых зависимостей. Она меняет служебную разметку, а не содержание статьи.

## Общий каркас

Каждая публикация получает одну внешнюю цепочку хлебных крошек перед `main`,
`container container--content` и один `article.content-card.article`.
Короткое название текущей страницы в крошках сохраняется. Родительские ссылки
соответствуют рубрике; JSON-LD BreadcrumbList согласован с видимой цепочкой.

Первый дочерний блок статьи — `header.article-header`. В нём последовательно
расположены подпись типа, исходный H1, исходные метаданные, редакционная дата
обновления при её наличии и статус актуальности памятки. Существующие `p` и `dl`
внутри компонента метаданных допустимы: их содержание и семантика сохранены,
а положение и отступы согласованы. Редакционные предупреждения, вводные абзацы,
изображения и тематические секции не переписываются.

Последний дочерний блок — один `nav.series-nav`. Он никогда не вложен в последний
тематический раздел статьи и не заменяется неоформленным `article-nav`.

| Тип | Оглавление | Нижние переходы | Особенность |
| --- | --- | --- | --- |
| Оценка | В конце текста, перед series-nav | Соседние оценки по дате публикации | Существующее зелёное оформление, период и статус сохранены |
| Материал о Кременной | Перед первым основным разделом | Соседние материалы Кременной по дате публикации | Исторические статьи сохраняют свою структуру и содержание |
| Другие статьи | Перед первым основным разделом | Соседние статьи той же рубрики | Гражданские последствия, СВО, ЛНР и политика не смешиваются |
| Памятка | Перед первым основным разделом | Существующий тематический подбор | Статус актуальности после метаданных; нет ложной хронологии |
| Досье | Перед первым основным разделом | По дате публикации, а не дате события | Существующее красное оформление сохранено |

## Оглавление

Оглавление строится из H2 в порядке чтения. Ссылки используют существующие ID;
у заголовка без ID добавляется свободный `content-section-N`. Имеющиеся ID
не переименовываются и не удаляются. Названия пунктов совпадают с текущими H2.
Заключение, связанные материалы и источники не теряются из навигации.

Отдельный датированный блок редакционного обновления не считается основным
разделом оглавления. При менее чем трёх остальных H2 оглавление не добавляется.
Так сохраняется отсутствие лишнего оглавления у трёх ранних коротких материалов.
Вводные блоки вне основного раздела остаются перед оглавлением. Если весь основной
текст заключён в одну секцию, оглавление стоит перед этой секцией; саму секцию
сборка не разрезает и не переписывает.

## Соседние и связанные публикации

Существующий компонент series-nav получает полные текущие названия из каталога.
Добавление очередной оценки или статьи автоматически обновляет переход предыдущей.
Пропущенные календарные недели не превращаются в несуществующие ссылки.
У первого/последнего материала свободную позицию занимает ссылка на раздел
с подписью «Раздел», без притворного «следующего» или «предыдущего» материала.

У памяток сохраняются существующие тематические цели и осмысленные подписи
«Базовая памятка», «По сроку», «Контакты города» и т. п. Общие подписи
«Предыдущий/Следующий материал» заменяются на «Связанная памятка», поскольку
эта рубрика смешивала тематический подбор и хронологию. Если нижнего блока ещё
нет, используются до двух ссылок из авторского раздела связанных памяток;
при отсутствии такой подборки остаётся ссылка на справочник. Новые рекомендации
из содержания автоматически не изобретаются.

## Что проверяется

`npm run validate` теперь проверяет каркас всех публикаций, полноту и положение
оглавлений, соседние переходы, совпадение подписей с каталогом, метаданные,
крошки, responsive sizes, а также одинаковые шапки и футеры всех страниц.
Это проверка, а не автоматическое исправление не прошедшего валидацию HTML.

`npm run test:uniformity` проверяет поисковое состояние, задержанную загрузку
индекса, сброс, историю, сохранение сторонних URL-параметров, полную выдачу,
даты в результатах и повторяемость нормализации всего каталога.
Команда включена в `npm run qa`. Браузерные сценарии находятся в
`tests/e2e/uniformity.spec.mjs` и выполняются штатным Playwright вместе с остальными.
Негативные тесты намеренно восстанавливают выявленные поломки и требуют отказа валидатора.

## Сохранность содержания и новый выпуск

Алгоритм и формат `content-integrity-v2` не ослаблены и не заменены. Старый контроль
учитывает также текст оглавлений и ссылки навигации. Поэтому после осознанного
добавления/редактуры публикации сначала нужно собрать служебные блоки, затем
зафиксировать проверенный результат:

```bash
npm run images
npm run build
npm run content:lock
npm run qa
```

Не запускайте `content:lock` просто для подавления неожиданного изменения текста.
Сначала просмотрите diff. В данном патче контроль обновлён только после отдельного
сравнения основного текста, заголовков, ссылок, подписей, изображений и метаданных
всех 77 публикаций с исходным ZIP. Поисковый индекс остался побайтно прежним.

При добавлении статьи продолжают использоваться HTML и `data/pages.json`.
Новая структура данных, CMS, маршруты, источники контента и сервисы не вводятся.
Даты публикаций и `lastmod` от технической унификации не повышаются.

## Границы патча

Не меняются формулировки статей, даже спорные даты внутри старых редакционных
обновлений, кириллическое написание бренда или смешанные буквы в двух словах.
Это отдельные текстовые правки; для унификации компонентов они не нужны.
Не меняются набор и порядок материалов главной. При равном приоритете отбора
теперь явно используется уже существующая сортировка по дате; текущий результат
тот же. Фотографии не обрезаются заново, файлы изображений не пересоздаются.

Версия собственных CSS/JS повышена только для штатного обновления браузерного кэша.
Футер сохраняет прежний вид: удалены перекрытые декларации, а не увеличен шрифт.
У карты восстановлен существующий цвет фокуса; код и данные карты не меняются.
Шапки/футеры остаются статическим HTML, но их расхождение блокирует выпуск.

Автоматические проверки не заменяют просмотр `dist/` на desktop/mobile.
Патч сам ничего не коммитит, не отправляет в GitHub и не публикует.
