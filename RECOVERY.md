# Восстановление KRM РФ

Цель: восстановить сайт только из релизного ZIP, даже если GitHub или Cloudflare недоступны.

## Что должно храниться независимо

Минимум четыре копии:

1. репозиторий GitHub;
2. локальная рабочая копия;
3. датированный release ZIP на отдельном физическом носителе;
4. ещё одна независимая копия вне основного компьютера.

Cloudflare Pages не считается резервной копией.

В независимом защищённом документе, не в репозитории, должны храниться сведения о доступе к домену, DNS, GitHub, Cloudflare, электронной почте, 2FA и резервным кодам.

## Проверка архива

Рядом с ZIP находится файл `.sha256`.

Linux/macOS:

```bash
sha256sum -c krmrf-site-2026.6.20-r4.zip.sha256
```

После распаковки:

```bash
cd krmrf-main
npm run fixity
npm run check
```

## Локальный запуск

Требуется Node.js 20 или новее.

```bash
npm run serve
```

Откройте `http://localhost:8000/`.

Основное содержание доступно как обычные HTML-файлы. Без Node.js публикации можно читать, но для проверки и новой сборки Node.js необходим.

## Развёртывание без Cloudflare

Сайт не требует сервера приложений или базы данных. После `npm run check` опубликуйте содержимое корня на любом статическом хостинге.

Необходимо поддержать:

- HTTPS;
- файл `404.html`;
- правила `_redirects` или их аналоги;
- заголовки из `_headers` или их аналоги;
- корневой домен и пути с завершающим `/`.

Перед переносом временно сохраните прежний домен и настройте 301-редиректы, если это возможно.

## Восстановление после потери GitHub

1. проверьте SHA-256 release ZIP;
2. распакуйте архив;
3. выполните `npm run check`;
4. создайте новый закрытый или публичный репозиторий;
5. выполните первый commit;
6. подключите новый статический хостинг;
7. настройте DNS;
8. проверьте главную, публикации, архив, поиск, карту и 404.

## Восстановление после повреждения файлов

```bash
npm run fixity
```

Команда перечислит отсутствующие или изменённые файлы. Не заменяйте повреждённый релиз частично: восстановите его из другой проверенной копии.

## Проверка преемником

Человек, который впервые видит проект, должен суметь:

1. прочитать `README.md`, `PUBLISHING.md`, `SOURCES.md` и этот файл;
2. выполнить `npm run check`;
3. запустить сайт;
4. создать тестовую публикацию в отдельной ветке;
5. создать release ZIP;
6. восстановить его в новой папке.

Проводите такой тест не реже одного раза в квартал и после крупных изменений сборщика.
