# Работа с KRM РФ

- Исходники публикаций — существующие HTML и `data/pages.json`. Производные карточки, поиск, sitemap и `dist/` собираются командой `npm run build`; не исправляйте их отдельно.
- `datePublished` сохраняется. `dateModified` меняется при содержательной правке; `reviewedAt` — только после фактического просмотра источников. Не продлевайте всем материалам даты ради зелёной проверки.
- Досье идут по `dateModified`; бессрочные `home.dossier` не применять. После изменения фактов проверить `excerpt`, SEO и журнал редакций. Новые записи Кременского досье редактируются в `data/dossier-events.json`; дата сводки и дата события различаются.
- Не складывать числа погибших и пострадавших из разных сводок без персональной сверки. Первоначальные 21/85 — исторический показатель, а не текущий счётчик. Самоссылка KRM не является независимым подтверждением.
- Старую хронику сохранять как датированный срез. Позднейшее уточнение добавлять отдельно с источником. `chronicleSeries` связывает регулярные выпуски автоматически; публицистику и справочные объяснения к серии не относить.
- После просмотра diff фиксировать только сознательно изменённые ID через `npm run content:lock -- --id=ID`. Не отключать контроль текста.
- Проверки: `npm run qa:visible`; отдельно `npm run test:negative` перед релизом. Не запускать две QA одновременно. Если проверку блокирует среда, указать точную причину, а не заявлять об успехе.
- Проверять изменения в `noviy-sait`. Публикация в `main` — отдельное действие владельца. Не включать в исходный ZIP зависимости, `dist/`, локальные журналы и временные файлы; постоянный архив карты сохранять.
